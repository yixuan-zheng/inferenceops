# Release validation

The curated source was validated independently of the private development archive: a new Python environment installed the public dependency files, downloaded the official checkpoint into a new checkout-local cache, exported the graph, and ran the complete 43-test suite. No archived ONNX binary, old virtual environment, absolute home path or hidden fixture was used. The regenerated model passed numerical/reference-transform validation. A different ONNX graph hash after re-export is recorded locally; numerical parity is the portable contract.

The public Dockerfile was rebuilt without dependency cache, the Linux ARM64 Compose stack started, and a public smoke command verified readiness, CPU provider/single worker, a real inference response, metric exposition, a healthy Prometheus scrape, and the provisioned Grafana dashboard. Monitoring startup uses bounded readiness polling, avoiding assumptions that a running container has finished provisioning. The real Grafana screenshot contains only this application's illustrative telemetry; it is separate from the original 42-run comparison.

The published numeric run table is independently checked for request accounting and aggregate mean/SD claims. Syntax/dependency consistency checks pass. CI repeats CPU tests, fresh model export, build and deployment smoke validation on an ARM64 hosted runner. It does not rerun an optimization study. A known upstream Starlette TestClient deprecation warning remains; tests pass with the pinned versions.

A fresh public-only Git history uses generic contributor metadata. All intended public files and every Git blob/commit object are reviewed for home paths, local identifiers, private hosts/networks, common secret formats, large generated files and local artifacts. Images are visually inspected and carry no personal desktop/browser content. Only source, selected numeric evidence/plots, generic fixture, final docs, monitoring and required provenance/notices are published. This review reduces accidental disclosure risk; it is not a guarantee against every possible secret format.

Operational/reproduction limits remain: first setup needs internet and external upstream availability; measured deployment is Linux ARM64 on one local CPU-limited host; weights have upstream terms distinct from project MIT code; running native calls cannot be forcibly interrupted; and measured performance is not an accuracy or production reliability claim.
